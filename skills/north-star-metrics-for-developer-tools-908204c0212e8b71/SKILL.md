## TL;DR

A north star metric aligns the whole team on the one number that captures value delivered.
For devtools it usually sits at the moment the tool does its job, not at signup.
Applies to developer tools with real usage to measure.

## The query

```text
north star metrics for developer tools
```

## Use this when

- You are defining product metrics for a developer tool.
- The team needs one number capturing value delivered.
- The product has real usage to measure.

## Not for

- You need a full metrics dashboard (the north star is one number, not a dashboard).
- The product has no users yet (pick a leading indicator instead).
- Leadership wants the metric to always go up (a north star must be allowed to move honestly).

## Steps

1. List the moments users get value: the successful run, the resolved issue, the shipped artifact.
   Expected output: Candidate value moments grounded in real usage.
2. Pick the one moment that best predicts retention and is measurable today.
   Expected output: A single metric definition with a clear counting rule.
3. Check it against the traps: it should resist gaming and reflect user value, not activity.
   Expected output: A metric you would defend in a hard quarter.
4. Instrument it, baseline it, and review it weekly with the team.
   Expected output: A living number the team actually uses to make decisions.
