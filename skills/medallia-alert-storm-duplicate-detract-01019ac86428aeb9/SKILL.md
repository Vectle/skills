## TL;DR
Fix this in Medallia alert storm by acting on the exact problem first: dedupe detractor alerts on response identifier before notifications are sent, hold alerts generated by a batch import until the batch is fully deduped, and cancel the duplicate alerts already queued while keeping the first alert per response. Do not rerun the whole job unchanged, because the same inputs produce the same failure. Prove the fix on one response, batch or record set first, then rerun the full scope and reconcile the counts.

## Why it happens
The import processed some responses twice as the batch was retried, and each processing run generated its own alert, so one detractor produced a storm of identical notifications.
