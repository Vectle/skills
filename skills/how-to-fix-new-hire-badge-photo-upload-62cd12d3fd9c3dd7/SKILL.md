## Why it happens
Repeated uploads of the same file keep failing the same hidden rule, and testing each rule before re-uploading turns a guessing game into a single corrected attempt with the accepted specs captured for the guide.

## Edge cases
- The hire record was edited, the start date moved or the manager changed after the failing run started. Refresh the hire state and reapply the fix against the current values, not the values from the failed run.
- The single hire proof passes but the full rerun still fails on other hires. Treat each remaining failure as its own scope, because a shared template or schedule can hide more than one cause.
- The source systems disagree on the correct value. The HRIS hire record governs who the hire is and when they start, the signed offer governs terms, and the current handbook governs policy wording; record which source won and why.
