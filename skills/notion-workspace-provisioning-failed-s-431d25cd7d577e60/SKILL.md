## TL;DR
Replace the expired or wrong SCIM credential in the identity provider and test the connection before resuming sync. Generate a fresh SCIM credential in the Notion workspace settings as an owner, paste it into the identity platform provisioning configuration for the Notion app without extra spaces, run the connection test, and provision one user to prove the path end to end.

```text
Notion workspace provisioning failed: SCIM token authentication error 401
```

## Use this when
- Entra ID or Okta provisioning to Notion fails every operation with a 401 response.
- The failure started suddenly, often after a workspace owner change or a credential cleanup.
- Notion workspace itself is reachable and members sign in normally.

## Not for this skill when
- Only one user fails provisioning with a validation error. That is record data, not authentication.
- Notion is unreachable entirely. Check network and vendor status first.

## Steps
1. Confirm the scope from the identity platform provisioning logs: every user and every operation failing with 401 at the same start time points to the credential, while mixed results point elsewhere. Note the exact start time for correlation with workspace changes. Verify: the failure is global to the Notion connection from a known start time
2. In Notion, as a workspace owner, open Settings, Connections or the SCIM provisioning section depending on plan, and review the current provisioning configuration state, including whether a credential was recently regenerated by someone else, which invalidates the previous one immediately. Verify: the workspace provisioning state and any recent regeneration are known
3. Generate a fresh SCIM credential in Notion and copy it directly into the identity platform Notion app provisioning credentials field in the same session, taking care to copy the full value with no leading or trailing spaces and to save it in the credential field rather than a notes field. Do not store the value anywhere else. Verify: the identity platform saves the new credential without a format warning
4. Run the provisioning test connection from the identity platform and confirm it returns success, then check the Notion workspace member list for the test effects if the platform performs a read. A successful test proves authentication and basic authorization together. Verify: the test connection reports success
5. Provision one real user on demand, confirm the Notion member appears with the correct email and name, then restart the full provisioning job and watch the first cycle clear the backlog of failed users. Verify: the single user provisions and the full cycle runs without 401 responses
6. Record the credential ownership and rotation date in the team credential inventory without recording the value, and assign a single owner workspace admin for future rotations so the identity platform is updated in the same change. Verify: the inventory entry exists with owner and date only

## Why it happens
A 401 from a SCIM endpoint means the credential presented is missing, malformed, expired, or revoked, and Notion regenerating a credential revokes the old one instantly, so any out-of-band regeneration breaks the identity platform until it receives the new value. Because the failure is total and sudden, it is distinguishable from per-user data errors. The fix is a coordinated rotation in one session so no window exists where the two sides hold different values, followed by a connection test that proves both authentication and the provisioning path before the backlog retries.

## Variants and edge cases
### 401 returns right after a successful rotation
A second workspace owner may have regenerated again, or the identity platform cached the old value. Regenerate once more with all owners notified and restart the provisioning job to clear any cache.

### Test connection passes but creates still 401
Some platforms test with a read that uses a different permission than writes. Provision the single test user as the real proof and check workspace plan SCIM entitlements.

### Notion plan downgrade removed SCIM
If the workspace plan no longer includes SCIM, credentials cannot work. Restore the required plan level or switch provisioning to manual membership management.

Compatibility: Applies to Notion Plus, Business, and Enterprise workspaces with SCIM provisioning from Okta or Entra ID. Requires a Notion workspace owner for credential steps.
