## TL;DR

A directory listing converts when the first line states the problem it solves, the description shows the tool doing it, and there is one clear next step. Lead with the user's pain, follow with what the tool does about it, add one proof point, and end with the single action to take. Cut everything else.

```text
how to write a directory listing that converts
```

## Use this when

- Drafting a new directory listing
- Rewriting an underperforming listing
- Adapting listing copy to a new directory's format

## Not for this skill when

- The directory dictates the exact format (follow it instead)
- You have no proof points yet (ship without them, add later)
- The tool's positioning is still unsettled (settle it first)

## Steps

1. Write the one-liner as problem plus outcome. "Find X without Y" beats "A blazing-fast Z platform". Expected: a stranger gets it in five seconds.

2. Open the description with the pain. Two sentences on the problem, then what the tool does about it. Expected: the reader nods before they learn the features.

3. Add one proof point. Users, usage stat, or a concrete result. One is enough; five reads as bragging. Expected: a credibility anchor in the copy.

4. End with a single next step. Docs, quickstart, or live demo, pick one per directory. Expected: the reader knows exactly where to click.

```
listing structure:
  line 1: problem + outcome
  para:   the pain, then the fix
  proof:  one concrete proof point
  cta:    one link, one action
```

5. Cut ruthlessly. Remove adjectives, remove feature lists, remove anything that does not serve the four parts. Expected: the listing is shorter than your first draft by a third.

## Variant phrasings

### devtool listing copy that drives signups

Problem-first one-liner, pain-led description, one proof point, one call to action.

### how to describe a tool in a directory

Say what pain it kills and what happens next, not what it is built with.

### writing a converting product listing

Four parts: hook line, pain plus fix, proof, single next step. Cut the rest.

## Why it happens

Directory visitors skim dozens of listings in minutes. The ones that convert answer "is this for my problem" instantly; the ones that do not make the visitor work to figure out what the tool even does. Clarity converts, completeness does not.

## Edge cases / pitfalls

- Different directories allow different lengths; keep a short, medium, and long version.
- Never claim what the tool cannot do; directory visitors punish hype in reviews.
- Update the proof point as it improves; stale numbers hurt more than none.
- Match the directory's tone; a playful directory and an enterprise one need different copy.
