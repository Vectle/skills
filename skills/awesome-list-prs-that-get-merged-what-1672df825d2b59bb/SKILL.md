## TL;DR

Awesome-list PRs get merged when they follow the list's contributing guide exactly: correct section, alphabetical placement, the list's link-and-description format, and a neutral one-liner that proves fit. Maintainers reject PRs that ignore the format, read like ads, or stretch the list's scope. Read the guide, match the format, keep it factual, and accept the verdict gracefully.

```text
awesome-list PRs that get merged: what maintainers want
```

## Use this when

- Opening a pull request to an awesome list
- A previous PR was closed and you want to fix it
- Choosing which lists are worth the effort

## Not for this skill when

- The list has no contributing guide and no recent merges (probably dead)
- Your tool does not fit the list's scope (do not stretch it)
- You plan to argue if it gets closed (walk away instead)

## Steps

1. Read the contributing guide and recent merged PRs. The guide states the format; merged PRs show what actually passes. Expected: you can describe the list's format rules from memory.

2. Verify fit honestly. Does your tool belong in this list's scope, or are you stretching? Maintainers can tell. Expected: a yes you can defend in one sentence.

3. Place the entry correctly. Right section, alphabetical order, exact link format the list uses. Expected: the diff is minimal and clean.

```
PR checklist:
  section: correct, per the guide
  order: alphabetical within section
  format: matches existing entries exactly
  description: one neutral line, no superlatives
```

4. Write a factual one-liner. What it does, plainly. No "best", "revolutionary", "game-changing". Expected: the line reads like the others on the list.

5. Open the PR and leave it alone. One PR per list, no bumping, no duplicate PRs. Expected: a clean PR the maintainer can merge in one click.

## Variant phrasings

### how to get added to an awesome list

Match the contributing guide exactly, prove scope fit, write a neutral one-liner, and do not bump the PR.

### awesome list contribution guidelines

Read the guide, study merged PRs, place alphabetically, keep the description factual.

### why was my awesome list PR closed

Usually format mismatch, scope stretch, or ad-like copy. Read the close reason, fix or move on.

## Why it happens

Awesome lists are curated by volunteers protecting a signal-to-noise ratio. A PR that follows the format is cheap to review and merge; one that does not is work. Maintainers optimize for their own time, so format compliance is the highest-leverage thing you control.

## Edge cases / pitfalls

- Some lists require the project to meet criteria like stars, age, or license; check before PRing.
- Do not PR the same tool to ten lists in a day from a fresh account; pace it.
- If the maintainer closes without comment, do not reopen; note it and move on.
- Keep a list of merged PRs; they are social proof for the next list.
