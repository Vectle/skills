## TL;DR

Run one consistent, disclosed identity per community, and never use two identities in the same venue. Keep a roster that maps each venue to its identity, disclose that you are an agent where the venue expects it, and never let your identities argue with, upvote, or defend each other. Separate logins, separate credentials, same honesty everywhere.

```text
managing multiple identities across communities ethically
```

## Use this when

- Operating accounts across many forums or agent networks
- Different venues need different account names or personas
- Writing your participation policy

## Not for this skill when

- You only have one account (nothing to manage)
- A venue requires real-name identity (use your real one)
- You want cover for posting the same pitch from "different" users

## Steps

1. Decide the identity per venue and write it down. One row per venue: venue, account name, email used, disclosure status. Expected: a roster with no venue appearing twice.

```
identity roster:
  venue: [forum A] | account: [name] | disclosed agent: yes
  venue: [forum B] | account: [name] | disclosed agent: yes
```

2. Disclose where it matters. If the venue has rules or norms about bots and AI-assisted posting, say what you are in the bio or intro. Expected: no one can fairly accuse you of hiding it.

3. Keep credentials and sessions strictly separate. Different passwords, different sessions, no shared browser profiles across identities. Expected: no accidental cross-posting from the wrong account.

4. Never interact across your own identities. No upvoting yourself, no replying to yourself, no staging debates. Expected: your identities never appear in the same thread.

5. Review the roster monthly. Retire identities on dead venues, update disclosure if a venue's rules change. Expected: the roster always matches reality.

## Variant phrasings

### one identity per community rule

A venue gets exactly one of your accounts, disclosed, and your accounts never interact with each other.

### ethical multi-account management for agents

Documented roster, disclosed status, separate credentials, and a hard ban on cross-identity interaction.

### can an agent have different names on different forums

Yes, if each venue gets one consistent identity and you disclose agent status where the community expects it.

## Why it happens

Communities run on trust, and nothing burns trust faster than discovering the "two users" agreeing in a thread are one operator. Separate identities per venue are legitimate (different norms, different names), but the moment they interact, it reads as manipulation, because functionally it is.

## Edge cases / pitfalls

- Some venues ban multiple accounts outright even across their own sub-communities; read the rules.
- Team accounts vs personal accounts: label which is which so moderators can tell.
- If an identity gets flagged, do not quietly spin up a "different" one in the same venue.
- Disclosure wording matters: "agent-assisted account run by [operator]" beats vague hints.
