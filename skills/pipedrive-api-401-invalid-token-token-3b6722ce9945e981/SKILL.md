## TL;DR

The Pipedrive API token is wrong, stale, or revoked. Copy a fresh token from the user's Pipedrive settings, under personal preferences in the API section, into the client, and the 401 clears. Confirm the client sends it the way the endpoint expects.

The token is dead. Replace it, do not debug around it.

## Verbatim query

```text
pipedrive API 401: Invalid token - Token not found
```

## Steps

1. Copy a fresh API token from Pipedrive settings
   Open the user's personal preferences, find the API section, and copy the token exactly.
   Expected: A fresh token string with no extra whitespace.

2. Update the client configuration
   Replace the old token wherever the generated client stores it.
   Expected: The client sends the new token on the next request.

3. Make a simple test call
   Hit a lightweight endpoint like the users/me endpoint and confirm authentication works.
   Expected: A 200 response instead of the 401.

4. Confirm the company domain is correct
   Pipedrive API URLs include the company subdomain. A wrong subdomain can compound token confusion.
   Expected: The base URL matches the company the token belongs to.

5. Move the token out of hardcoded client code
   Store it in configuration or a secret store so the next rotation does not need a code change.
   Expected: Token updates happen in config, not in source.

## Use this when

- Pipedrive returns 401 "Invalid token - Token not found" on any endpoint.
- A previously working integration suddenly fails every call.
- The token may have been regenerated by the user in settings.

## Not for this skill when

- The error is a 403, which is a permissions problem rather than a bad token.
- The integration uses Pipedrive OAuth rather than personal API tokens.
- The failure is a wrong company-domain URL rather than a token problem.

## Variant phrasings

### "Token not found" on deals, persons, or any endpoint

The endpoint does not matter. A dead token fails everywhere identically.

## Why it happens

Pipedrive personal API tokens are per-user and can be regenerated at any time from settings, instantly killing the old one. Generated clients typically embed the token once during development with no rotation path. The integration then works until someone regenerates the token, and fails on every call from that moment on.

## Edge cases

- Tokens copied with trailing whitespace or line breaks fail; trim on paste.
- A deactivated Pipedrive user invalidates their token; check the user is still active.
- The company subdomain in the URL must match the token's company.
- Do not confuse the personal API token with OAuth access tokens; they are different credentials for different flows.
- Sandbox and production companies have separate tokens.
