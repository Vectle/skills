## TL;DR
A cracked screen should mean minutes of user downtime, not days: keep a pool of ready loaners, swap the device at the desk, image or enroll the loaner to the user, and send the damaged unit for repair. Track the loaner so it comes back.

## The query
```text
how to handle a cracked laptop screen: loaner swap workflow
```

## Use this when
- user reports a cracked laptop screen
- running the loaner pool day to day
- reducing downtime for hardware damage

## Not for
- the warranty claim with the vendor (separate process)
- data recovery from a dead machine
- damage caused by policy violations (still swap first, investigate after)

## Steps
1. Log the damage ticket with photos and the asset tag. Expected output: damage documented
2. Hand the user a ready loaner from the pool and confirm they can sign in. Expected output: user working again within the hour
3. Record the loaner assignment with a due date in the asset system. Expected output: the loan tracked
4. Send the damaged device for screen repair or vendor service. Expected output: repair in motion
5. When repaired, wipe or reimage it and return it to the loaner pool. Expected output: pool replenished
6. Close the loop with the user and reclaim the loaner. Expected output: no loaners lost
